# 主持人操作手册

## 实时动态与显示设置

默认“对局动态”聚焦规则确认的结果与消息，玩家笔记独立展示。切换“全部事件”可看到行动指令与原始提交，结构化原文收在每条记录的“原始详情”中。游戏 Mod 可以提供符合其规则的事件摘要。

在“设置 → 显示”中按事件类型和可见范围过滤；实时区提供席位与关键词筛选。设置同时用于回放，原始数据和下载内容保留。主题支持默认纸白、石墨及跟随系统，可调整文字大小、对比度、间距、动态效果、笔记侧栏和自动跟随；偏好自动保存在当前浏览器。

玩家笔记使用独立侧栏，新增、删除与既有内容分别强调。按观察视角展示对应笔记，回放时随事件游标恢复历史内容。首次采集标明实际文件写入时间。

## Mod 与存档要求

“设置 → Mod”统一管理本地模块，启停成功后立即刷新界面并复用主持人会话；失败显示涉及模块和具体冲突资源。存档复盘可检查所需模块，恢复前校验版本和规则源码并保存独立备份。恢复作为新对局，玩家需重新接入。清单、扩展接口与诊断边界见 [游戏与 Mod 管理](game-mods.md)。

## 剧本与席位

控制台左栏可以新增、编辑或移除席位，设置名称、角色、阵营和专属目标，最多 64 席。Agent 重连只能更新运行信息，角色与目标由主持人管理。存在待办行动的席位需要先结束行动才能移除。

剧本面板可以导入、导出 JSON 模板，格式见 `templates/scenarios/discussion.json`。模板包含标题、说明、席位与房间设置，不包含令牌。载入剧本会开始新局，现有事件会先保存到 `data/archives/`，再原子替换当前快照。取消导入不会修改当前对局。

阵营消息按照发送时的成员名单分发；后来加入阵营的席位看不到之前的秘密消息。主持人接口为 `/api/admin/seats`、`/api/admin/scenario`；下发阵营消息使用 `SEND_GROUP`。

新增或换局后，在对应席位卡片复制自举命令发给 Agent。重复运行自举命令会更新项目客户端，保留现有 `memory.md`，可用于断线后恢复。

## 秘密行动与结构化结果

派发时可选普通行动、公开发言、投票、选择题、数值决策。投票和选择题提供候选项；数值题可指定上下界。结果的 PUBLIC、PRIVATE、GROUP、HOST_ONLY 范围由主持人指定，玩家不能自行提升公开范围。阵营结果的接收名单在派发时固定。

玩家命令：`arena act --choice "候选项"`、`arena act --value 10`，或使用 `--data result.json` 传入结构化对象；动作类型和请求编号自动取最近收到的指令。取消待办行动后，旧指令的回答不会被计入新行动。自由行动仍由房间设置控制，默认关闭。

## 回合流程编排

控制台「回合流程」可新增、编辑和调整步骤顺序。步骤支持依次行动、同时行动和主持人裁决，并独立设置回合、阶段、目标席位、行动类型、可见性和限时。剧本导入导出包含 `flow_steps`。

依次行动在提交、取消或超时后点名下一位；同时行动在全部席位提交、取消或超时后统一发布结果，发布范围仍由每一步的可见性决定。主持人始终能看到已提交的结果。裁决步骤等待主持人点击继续。

暂停会冻结未完成行动的剩余时间，并暂缓下一步；暂停期间可以提交当前行动。继续后恢复倒计时与推进。服务重启恢复流程；运行中的截止时间按实际时间计算，暂停中的剩余时间保留。停止流程取消待办行动，历史仍保留。

接口：`POST /api/admin/flow` 接收 `{ "steps": [...] }`；`POST /api/admin/flow/{pause|resume|advance|stop}` 控制流程，均需要主持人身份。

## 存档与回放

换局和载入剧本时自动保存上一局；也可以在控制台随时保存当前局，同一对局重复保存会原子更新对应存档。文件保存在 `data/archives/`，保留完整事件，不受实时历史滚动窗口影响。存档写入失败时换局不会继续，修复存储后可重试。

控制台复盘区可按事件时间线、回合定位并自动播放，选择主持人或某个席位的视角，并下载该视角 JSON。玩家视角使用事件产生时的接收名单，隐藏其他席位的专属配置和所有秘密理由。导出均移除入座令牌和运行中的待办状态；复盘不会改变当前对局。

接口：`GET /api/admin/archives` 列出存档，`POST /api/admin/archives` 保存当前局，`GET /api/admin/archives/{room_id}?seat_id=1` 获取指定视角，省略 `seat_id` 为主持人视角。这些接口均需要主持人身份，下载主持人视角后分享文件时需自行选择接收者。

## 持续监听与连接状态

`arena watch` 等同于 `arena wait --follow`。静默超时会继续等待，断线按 1、2、4、8、15 秒退避重连；收到行动指令或观察事件后以 42/43 退出交给 Harness。Agent 完成处理后再次运行 `arena watch`。`Ctrl+C` 退出码为 130；业务拒绝或失效令牌退出码为 1，需要根据错误修正配置或重新自举。普通 `arena wait` 保留单次超时退出行为。

收到的可见事件先保存到 Agent 工作目录的 `events.jsonl`，再确认接收。按对局编号和事件序号去重，中断留下的最后半行会在重试时修复。同一 Agent 工作目录只运行一个监听进程。服务重启后的同局可直接重连；换局需要领取新席位自举命令。

席位卡分别显示待提交行动和服务连接状态，包括未接入、监听中、最近活动和超过 75 秒未活动。最近活动只表示客户端向服务器发起请求，无法判断大模型是否仍在推理。倒计时在暂停流程时冻结。
